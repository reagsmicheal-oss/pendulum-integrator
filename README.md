# pendulum-integrator
Forward-Euler pendulum simulation with small-angle validation and energy-drift analysis
Browsing the scipy issue tracker under scipy.integrate, a recurring theme is that many issues and doc requests ask for clearer, worked examples showing the accuracy/cost trade-off between fixed-step methods (like Euler) and SciPy's adaptive solve_ivp, rather than just API reference pages. This is a good issue for me to contribute to because it doesn't require deep knowledge of SciPy's internals — it just needs a well-commented, correct example. I already have exactly this: my pendulum integrator compares a hand-rolled Euler scheme against the small-angle analytic solution and quantifies energy drift as a function of step size Δt. I could adapt this into a documentation PR that (1) integrates the same pendulum problem with solve_ivp (both fixed-step and adaptive-tolerance modes), (2) plots θ(t) and energy drift for Euler vs. solve_ivp on the same axes, and (3) briefly discusses why adaptive step control avoids the drift my Euler results show. It's a small, self-contained contribution, but it turns a chapter exercise into something that actually improves a widely-used open-source project's documentation
Script runs cleanly and the numbers make the point nicely: Euler drifts by ~1.8 J over 10 s using 1000 evaluations, forced-small-step RK45 essentially eliminates drift but costs 6x more evaluations, and default adaptive RK45 gets drift down to ~0.008 J using fewer evaluations than Euler. That's the accuracy/cost trade-off the exercise wants illustrated
